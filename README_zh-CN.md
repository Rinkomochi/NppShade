# NppShade：在 Notepad++ 中给文本加密

[中文](README_zh-CN.md) · [English](README.md) · [日本語](README_ja-JP.md) · [한국어](README_ko-KR.md)

NppShade 可以把文本加密成需要密码才能读取的内容，也可以计算哈希、生成随机数据和转换 Base64 等编码。界面支持简体中文、英文、日文和韩文；默认跟随 Windows 显示语言，也可在“首选项 → 界面语言”中手动选择。切换后对话框立即更新，插件菜单名称在重启 Notepad++ 后更新。

本项目由 [Rinkomochi](https://github.com/Rinkomochi/NppShade) 维护，源码复刻来自 [chcg/nppcrypt](https://github.com/chcg/nppcrypt)。

## 安装或更新

1. 在 Notepad++ 的“关于”里确认程序位数，并下载相同位数的 x86 或 x64 安装包。
2. 保存正在编辑的文件，退出 Notepad++。
3. 从 GitHub Release 下载与你的 Notepad++ 位数相符的 ZIP，解压到 `plugins/NppShade/` 文件夹。文件夹不存在就新建。
4. 重新启动，在“插件 → NppShade”中找到菜单。更新时替换同一位置的 DLL；最好先备份旧 DLL 和配置文件。

如果没有菜单，先检查 DLL 位数、目录位置，以及是否真的退出并重新启动了 Notepad++。安装到 Program Files 时，Windows 可能要求管理员权限。

配置文件保存在 Notepad++ 插件配置目录下的 `nppshade.xml`。如果只找到旧版 `nppcrypt.xml`，NppShade 会读取并迁移设置，之后写入 `nppshade.xml`。

GitHub 上以版本标签创建发行版时，工作流会自动构建 x86 和 x64 DLL，并将两个 ZIP 包附加到发行版。

## 第一次使用：给整个文件加密

先用一份无关紧要的测试笔记练习。

1. 打开“插件 → NppShade → 首选项”，在“整文件加密”中勾选“启用”。扩展名填写 `nppshade;enc;npp`，也可以只填 `nppshade`。点击“确定”。
2. 新建文件，输入 `这是我的第一份加密笔记`。建议使用 Notepad++ 的 UTF-8 编码。
3. **不要选中文字**，点击“插件 → NppShade → 加密”。选择保存位置，输入密码，再输入一次确认。记住这个密码，插件没有找回密码的功能。
4. 编辑器里仍可正常阅读和修改文字，但保存到磁盘的是密文。如果从已有的 `笔记.txt` 开始，通常会另存为 `笔记.txt.nppshade`，原来的明文文件会保留。
5. 你也可以将常用的后缀添加进去，比如 `nppshade;txt;ini`等。
6. 关闭并重新打开加密文件，输入密码。密码正确后才显示正文；解密失败时密码框保留，可重新输入或取消。

“保存时询问是否加密”控制保存时是否询问使用或更改加密设置。希望使用已记住的设置直接保存时，可以取消勾选。文件关闭后，该文件的密码不会继续用于自动保存；再次打开需要输入密码。

如果你取消了解密，编辑器中会保留密文。不要把它当正文修改后保存；可以关闭文件后重新打开，或选中完整密文，通过“解密”重试。

### 多个扩展名如何工作

用**英文分号**分隔，例如 `nppshade;enc;npp`。前后空格和前导点会清理，大小写不影响匹配，重复项只保留一次。不要填 `*.enc`、路径或 `tar.gz` 这样的多段后缀。

- 列表中的任意后缀都能触发整文件处理。
- 第一项是新建加密文件的默认后缀。
- 已有 `.enc` 文件不会因为第一项是 `nppshade` 就改名。
- 另存为时可填写任意已配置后缀；如果没有匹配后缀，则追加第一项。
- 后缀只是识别规则，改个后缀不会给文件加密。普通文本即使叫 `.enc`，首次打开也不会弹密码框；它还没有加密文件头。

## 只加密一段文字

1. 选中想保护的文字，再点击“加密”。选区会被包含文件头的密文替换，其他内容保持原样。
2. 保存文件。这种方式不会自动保护整个文件，未选中的文字仍是明文。
3. 解密时选中**完整的加密块**，包含 `<nppshade ...>` 文件头及后面的密文，然后点击“解密”并输入密码。

没有选区时，“加密”走整文件流程，需要启用扩展名处理；“解密”需要选区。带有效文件头的加密文件也可以直接打开，由插件自动处理。

## 密码与高级设置

一般只输入密码即可。首次加密需要确认密码，避免因为打错一个字而无法再打开文件。密码区分大小写；中文、空格和标点也属于密码的一部分。

自动打开加密文件时只显示密码输入界面，不显示“高级”按钮。文件头已经提供了算法等信息。手动解密带文件头的内容时，有“密码编码…”入口，用于以前以 Hex、Base32 或 Base64 输入密码的特殊情况。没有文件头的密文需要手动设置参数，保留完整界面。

加密窗口的“高级”包含以下选项。没有明确需要时，使用基本模式的默认设置即可：

| 位置 | 它的作用 | 初学者怎么选 |
| --- | --- | --- |
| 基本：算法、密钥长度、模式 | 决定如何加密正文 | 默认是 AES/Rijndael、256 位密钥、GCM；不要为已有文件随意更换参数 |
| 基本：密码编码 | 指定输入的是普通 UTF-8 密码，还是编码后的密钥字节 | 平时选 `utf8`；`base16/base32/base64` 是解释输入的方式，不是增强密码 |
| 基本：显示 | 临时显示输入的密码 | 确认周围没人能看到再使用 |
| 基本：验证 IV/盐 | 在支持认证的模式中一并校验这些参数 | 默认开启；它与预设 HMAC 密钥不是一回事 |
| 编码 | 把密文输出为二进制、Hex、Base32 或 Base64 | 文本笔记使用默认 Base64 更方便；换行和每行长度只影响排版 |
| 密钥：盐值 | 加入随机数据，使相同密码也能派生出不同密钥 | 默认使用随机盐，不必记住；它保存在文件头中 |
| 密钥：scrypt / bcrypt / PBKDF2 | 把密码转换成加密密钥，并提高反复猜密码的成本 | 保持默认 scrypt；参数越大通常越慢，部分参数会显著增加内存使用 |
| 初始向量（IV） | 为一次加密提供起始数据 | 选随机生成；不要随意使用全零或反复使用同一自定义 IV |
| 验证：HMAC | 用独立认证密钥校验文件头和密文 | 可选功能；默认 GCM 自身已有认证，不必为了基本使用额外配置 |

## 预设密钥：用来校验，不是解密密码

首选项里的预设密钥用于 HMAC，也可用于哈希窗口中支持密钥的算法。它不能代替正文的加密密码。

添加方式：在“名称”中填写用途，例如 `共享笔记校验`，点击“随机”生成值，再点击“添加”。值是 **16 字节数据的 Base64 编码**，通常为 24 个字符。插件最多保留 20 个预设，包含不可删除的默认项。

默认预设名为 `nppshade`。自定义预设以 Base64 保存到配置文件中，**Base64 不等于加密**。内置默认密钥公开，适合发现意外损坏，不能作为只有你知道的认证密码。若需要密码校验，应生成自己的密钥并保管好配置。

使用预设 HMAC 的文件记录的是预设编号。换电脑或分享文件时，需要相同密钥处于相同编号；删除排在前面的预设也可能改变后面项目的编号。先备份，别随意删掉旧文件仍在使用的密钥。

## 哈希：得到文字的“指纹”

选中文字，打开“哈希”，选择算法和输出编码。“插入”会把选区变成摘要，“复制”只把摘要放到剪贴板。要保留正文时选“复制”。一般用途可选 SHA-256；MD5 等旧算法不适合需要抵抗恶意伪造的校验。

摘要长度决定输出多少字节，编码决定这些字节如何显示。支持密钥的算法可以勾选“使用密钥”，再选预设或输入自定义值。别人要得到相同结果，文字、算法和密钥都必须一致。哈希不能还原原文，也不是给文字加密。

## 随机数据：生成密码或随机字节

打开“随机数据”，填写字节数，选择字符范围和输出编码。“插入”会替换当前选区；没有选区时插入到光标处。“复制”不改正文。

若想生成方便输入的随机密码，可选择二进制输出及 `[a-zA-Z0-9]` 或密码字符范围，再复制结果。二进制加“不限制字符”可能产生不可见字符，适合处理字节数据，不适合直接拿来当日常输入的密码。Hex、Base32、Base64 编码会让最终字符数大于原始字节数。

## 编码转换：文本与 Hex / Base32 / Base64 互转

选中文字，打开“编码转换”，在“来源”中选择当前格式，在“目标”中选择想要的格式。比如把 `hello` 从文本转成 Base64，结果是 `aGVsbG8=`；反向转换时来源选 Base64、目标选文本。

“转换”替换选区，“复制”保留原文。换行、每行长度和大写字母控制输出格式。编码是表示数据的方式，知道格式的人就能还原，不能用于保密。插件加密使用的 Base32 字母表与转换窗口的默认标准 Base32 不同，不要混用。

## 屏幕缩放与常见问题

窗口根据 Notepad++ 所在显示器的 DPI 调整控件和字体。移动到不同缩放的显示器时会重新布局；可用屏幕区域较小时会压缩布局并限制位置，尽量保证按钮可见。老版本 Notepad++ 的 DPI 支持可能限制跨显示器效果，建议使用较新的版本。

- **密码错误怎么办？** 解密失败后在原窗口重新输入。还应检查文件是否完整。GCM/CCM/EAX 等认证模式能发现密码或数据不匹配；某些不带认证的旧模式无法可靠识别错密码。
- **为什么文件里是密文，编辑器里却是正文？** 正文是在内存里编辑，保存时才加密。只有重新打开并输入密码，插件才能显示正文。
- **忘记密码能找回吗？** 不能。帮助问号只打开说明，不会显示或恢复密码；加密窗口的“显示”选项只会临时显示当前输入。请自行可靠地保管密码。
- **备份也会加密吗？** 本插件处理常规保存，不负责保护 Notepad++ 的会话快照、自动备份或其他软件的副本。注意原始明文文件也可能仍在磁盘上。
- **配置在哪？** 普通安装通常是 `%APPDATA%\Notepad++\plugins\config\nppshade.xml`；便携安装一般在本地 `plugins/config/`。修改配置前退出 Notepad++，并先备份。
- **有认证密钥提示是什么？** 文件启用了自定义 HMAC，先输入认证密钥，再输入正文密码。它们可以是两份不同的秘密。

## 从源码编译

安装 Visual Studio 2022 的“使用 C++ 的桌面开发”及 Windows SDK，在开发者 PowerShell 中运行：

```powershell
msbuild projects\msvc2017\nppshade.sln /m /t:nppshade /p:Configuration=Release /p:Platform=x64
```

本地 x64 构建输出为 `bin/nppshade/x64/Release/NppShade.dll`。旧版 `<nppcrypt>` 文件头仍可读取，新加密内容使用 `<nppshade>` 文件头。源码还保留命令行工具项目，其选项以工具的 `--help` 为准；桌面插件的预设密钥并不能直接在命令行工具中使用。

遇到问题请到 [项目主页](https://github.com/Rinkomochi/NppShade) 反馈，附上 Notepad++ 版本、插件版本和复现步骤，不要提交真实密码或私密文件。
