# NppShade: Notepad++ 用暗号化プラグイン

[中文](README_zh-CN.md) · [English](README.md) · [日本語](README_ja-JP.md) · [한국어](README_ko-KR.md)

NppShade はテキストの暗号化と復号、ハッシュ計算、乱数生成、Base16/Base32/Base64 変換を行います。画面は簡体字中国語、英語、日本語、韓国語に対応しています。既定では Windows の表示言語に従い、「設定 → 表示言語」で手動選択できます。ダイアログにはすぐ反映されますが、プラグインメニューの表示更新には Notepad++ の再起動が必要です。

開発・保守は [Rinkomochi](https://github.com/Rinkomochi/Nppcrypt-CN)。ソースの一部は [chcg/nppcrypt](https://github.com/chcg/nppcrypt) 由来で、元のライセンス表示を保持しています。

## インストールと更新

1. Notepad++ が x86 か x64 かを確認し、GitHub Releases から同じ種類の ZIP をダウンロードします。
2. 開いているファイルを保存し、Notepad++ を終了します。
3. ZIP を Notepad++ の `plugins/NppShade/` に展開します。フォルダーがなければ作成します。
4. Notepad++ を再起動し、「プラグイン → NppShade」を開きます。更新前に既存の DLL と設定ファイルをバックアップしてください。

メニューが表示されない場合は、DLL のビット数、配置場所、再起動を確認してください。Program Files へのコピーには管理者権限が必要な場合があります。設定ファイルはプラグイン設定フォルダーの `nppshade.xml` です。旧 `nppcrypt.xml` だけがある場合、設定を読み込んで新しいファイル名に移行します。

GitHub でバージョンタグからリリースを作成すると、x86 と x64 を自動ビルドし、それぞれの ZIP を添付します。

## ファイル全体を暗号化

まず、失っても問題のないテスト用ファイルで操作してください。

1. 「プラグイン → NppShade → 設定」を開き、「ファイル全体の暗号化」を有効にします。拡張子には `nppshade;enc;npp` を入力します。`nppshade` だけでも使えます。「OK」を押します。
2. UTF-8 の新規ファイルに短いメモを書きます。
3. 文字を選択せず「暗号化」を選び、保存先を決めてパスワードを二度入力します。パスワードを忘れると復元できません。
4. 編集中は平文が表示され、保存ファイルは暗号文です。`note.txt` から始めると、通常は `note.txt.nppshade` が作られ、元の平文ファイルも残ります。必要なら `txt` や `ini` なども拡張子に追加できます。
5. 暗号化ファイルを閉じて開き直し、パスワードを入力します。入力に失敗してもダイアログは閉じず、再入力またはキャンセルができます。

「保存時に暗号化を確認」は、保存時に暗号設定の変更を確認するかを指定します。オフにすると、記憶した設定でそのまま保存します。ファイルを閉じると保存用パスワードは解除され、再度開くと入力が必要です。

復号をキャンセルした場合、編集画面には暗号文が残ります。平文として編集・保存しないでください。ファイルを閉じて開き直すか、暗号ブロック全体を選択して再度復号します。

### 拡張子の扱い

拡張子は英語のセミコロンで区切ります（例: `nppshade;enc;npp`）。前後の空白と先頭のドットは削除され、大文字小文字は区別されず、重複は除かれます。`*.enc`、パス、`tar.gz` のような複数部分の拡張子は指定しないでください。

- リスト内の拡張子はどれもファイル全体の処理対象になります。
- 新しいファイルの保存名に登録済み拡張子がなければ、最初の拡張子が追加されます。
- 既存の `.enc` ファイルは、最初の項目が `nppshade` でも名前を変更しません。
- 拡張子を変えるだけでは暗号化されません。暗号ヘッダーのない平文ファイルを開いてもパスワード画面は表示されません。

## 選択範囲を暗号化

文字を選択して「暗号化」を選ぶと、選択範囲だけが暗号ブロックに置き換わり、周囲の文字は平文のままです。復号するには `<nppshade ...>` ヘッダーを含むブロック全体を選択して「復号」を選び、パスワードを入力します。

選択範囲がない場合、「暗号化」は拡張子処理を有効にしたファイル全体の暗号化を行います。「復号」には選択が必要です。有効なヘッダーを持つファイルは開くと自動的に処理されます。

## パスワードと詳細設定

初回の暗号化では、確認のためパスワードを二度入力します。大文字小文字は区別され、空白、記号、日本語もパスワードの一部です。ヘルプの「?」は説明を開くもので、パスワードを表示・復元しません。入力中のパスワードは「表示」で一時的に確認できます。

有効なヘッダー付きファイルを開く場合、アルゴリズム情報はヘッダーにあるためパスワード欄だけが表示されます。手動復号では、以前 Hex、Base32、Base64 で入力したパスワード向けの「パスワードのエンコード」も使えます。認識可能なヘッダーがないデータでは詳細設定が必要です。

通常は既定値を使ってください。主な詳細設定は次のとおりです。

| 項目 | 役割 | 通常の選択 |
| --- | --- | --- |
| 暗号方式、鍵長、モード | データの暗号化方法を指定 | AES/Rijndael、256 ビット、GCM |
| パスワードのエンコード | UTF-8 または符号化済み鍵バイトとして入力を解釈 | 通常は `utf8` |
| 表示 | 入力中のパスワードを一時表示 | 周囲から画面を見られないときだけ使用 |
| IV/ソルトの認証 | 対応方式でこれらの値も認証 | オンのままにする |
| 出力形式 | 暗号文をバイナリ、Hex、Base32、Base64 で表現 | テキストファイルでは Base64 |
| ソルト | 暗号化ごとに導出鍵を変える | ヘッダーに保存されるランダム値を使う |
| scrypt、bcrypt、PBKDF2 | 鍵を導出し、パスワード推測のコストを上げる | scrypt を使用。高い値は時間とメモリを使う |
| IV | 暗号化の初期データ | ランダムに生成し、ゼロや独自値の再利用を避ける |
| HMAC | 別の鍵でヘッダーと暗号文を認証 | 任意。既定の GCM にも認証機能があります |

## プリセット鍵

プリセット鍵は HMAC と鍵付きハッシュ用で、暗号化パスワードとは別です。組み込みのプリセット名は `nppshade` です。追加するには名前を入力し、「ランダム」、「追加」の順に押します。鍵は 16 バイトの Base64 表現（通常 24 文字）で保存されます。削除できない組み込み項目を含め、最大 20 個です。

独自のプリセット鍵は設定ファイルに保存されます。Base64 は暗号化ではありません。組み込み鍵は公開されているため、意図しない変更の検出以外には使わないでください。秘密の認証には独自の鍵を作成し、設定のバックアップを保管します。ファイルにはプリセット番号が記録されるため、別のパソコンでも同じ番号に同じ鍵が必要です。前の項目を削除すると番号がずれる場合があります。

## ハッシュ

文字を選択して「ハッシュ」を開きます。「挿入」は選択範囲をダイジェストに置換し、「コピー」は本文を変えずに結果をコピーします。本文を残す場合は「コピー」を使います。一般的な検査には SHA-256 が適しています。MD5 は意図的な偽造への対策には適しません。ハッシュから元の文字を戻したり、暗号化したりすることはできません。

ダイジェスト長は出力バイト数、エンコードは表示形式を指定します。鍵付き方式で同じ結果を得るには、入力、アルゴリズム、鍵がすべて一致する必要があります。

## 乱数

バイト数、文字の制限、出力形式を選びます。「挿入」は選択範囲を置き換え、選択がなければカーソル位置に挿入します。「コピー」は文書を変更しません。制限なしのバイナリには見えない文字が含まれ、手入力のパスワードには向きません。Hex、Base32、Base64 の文字数は元のバイト数より多くなります。

## エンコード変換

文字を選択して「エンコード変換」を開き、「変換元」に現在の形式、「変換先」に目的の形式を設定します。たとえば `hello` の Base64 は `aGVsbG8=` です。「変換」は選択範囲を置き換え、「コピー」は元の文字を残します。改行、行幅、大文字指定は書式だけを変えます。エンコードは元に戻せるため、秘密保持にはなりません。暗号ヘッダーと変換画面では既定の Base32 アルファベットが異なるため、混用しないでください。

## 画面とよくある質問

ダイアログは画面の DPI と作業領域に合わせて配置されます。古い Notepad++ では異なる拡大率のモニター間の動作に制限がある場合があります。

- **パスワードが拒否される:** パスワードとファイルの完全性を確認してください。GCM、CCM、EAX はパスワードやデータの不一致を検出しますが、認証のない古い方式では誤ったパスワードを確実に検出できない場合があります。
- **編集画面は平文なのにファイルは暗号文:** 編集中の本文はメモリ上にあり、保存時に暗号化されます。再表示するにはファイルを開き、パスワードを入力します。
- **忘れたパスワードを復元できるか:** できません。ヘルプ、プリセット鍵、拡張子の変更で暗号化を回避することはできません。
- **バックアップも暗号化されるか:** Notepad++ のセッションスナップショット、自動バックアップ、他のアプリが作るコピーはプラグインの管理外です。元の平文ファイルがディスクに残ることもあります。
- **設定ファイルの場所:** 通常は `%APPDATA%\Notepad++\plugins\config\nppshade.xml`、ポータブル版では `plugins/config/` です。編集前に Notepad++ を終了し、バックアップしてください。
- **認証鍵を求められる:** ファイルで独自 HMAC 鍵が使われています。本文の暗号化パスワードとは別の場合があります。

## ソースからビルド

Visual Studio 2022 の C++ デスクトップ開発ツールと Windows SDK をインストールし、Developer PowerShell で実行します。

```powershell
msbuild projects\msvc2017\nppshade.sln /m /t:nppshade /p:Configuration=Release /p:Platform=x64
```

x64 DLL の出力先は `bin/nppshade/x64/Release/NppShade.dll` です。新しい暗号化データには `<nppshade>` ヘッダーを使い、既存の `<nppcrypt>` ヘッダーも読み込めます。ソースにはコマンドラインツールも含まれます。使い方は `--help` を参照してください。デスクトップ版のプリセット鍵はコマンドラインツールでは直接使えません。

問題を報告する場合は [プロジェクトページ](https://github.com/Rinkomochi/Nppcrypt-CN) に Notepad++ とプラグインのバージョン、再現手順を記載してください。実際のパスワードや個人ファイルは添付しないでください。
