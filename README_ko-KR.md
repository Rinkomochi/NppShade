# NppShade: Notepad++ 암호화 플러그인

[中文](README_zh-CN.md) · [English](README.md) · [日本語](README_ja-JP.md) · [한국어](README_ko-KR.md)

NppShade는 텍스트 암호화와 복호화, 해시 계산, 난수 생성, Base16/Base32/Base64 변환을 제공합니다. 인터페이스는 중국어 간체, 영어, 일본어, 한국어를 지원합니다. 기본적으로 Windows 표시 언어를 따르며 “환경 설정 → 인터페이스 언어”에서 직접 고를 수 있습니다. 대화상자에는 즉시 적용되고 플러그인 메뉴 이름은 Notepad++를 다시 시작한 뒤 갱신됩니다.

개발 및 관리는 [Rinkomochi](https://github.com/Rinkomochi/NppShade)가 맡습니다. 소스 일부는 [chcg/nppcrypt](https://github.com/chcg/nppcrypt)에서 가져왔으며 원본 라이선스 표기를 유지합니다.

## 라이선스

NppShade 자체 코드는 GNU 일반 공중 사용 허가서 버전 2 또는 (선택에 따라) 이후 버전으로 배포됩니다. 자세한 내용은 [LICENSE](LICENSE)를 확인하세요. 타사 구성 요소는 각각의 라이선스를 따르며 [THIRD_PARTY_NOTICES.md](THIRD_PARTY_NOTICES.md)에 정리되어 있습니다. 릴리스 ZIP에도 라이선스 안내가 포함됩니다.

## 설치 및 업데이트

1. Notepad++가 x86인지 x64인지 확인하고 GitHub Releases에서 맞는 ZIP을 받습니다.
2. 열려 있는 파일을 저장하고 Notepad++를 종료합니다.
3. ZIP을 Notepad++ 설치 폴더의 `plugins/NppShade/`에 풉니다. 폴더가 없으면 만드세요.
4. Notepad++를 다시 실행하고 **플러그인 > NppShade**를 엽니다. 업데이트 전 기존 DLL과 설정 파일을 백업하세요.

메뉴가 보이지 않으면 아키텍처, 경로와 재시작 여부를 확인하세요. Program Files에 복사할 때 관리자 권한이 필요할 수 있습니다. 설정 파일은 플러그인 설정 폴더의 `nppshade.xml`입니다. 예전 `nppcrypt.xml`만 있으면 NppShade가 설정을 읽고 새 파일명으로 옮깁니다.

GitHub에서 버전 태그로 릴리스를 만들면 x86 및 x64 DLL을 자동 빌드하고 각각의 ZIP을 릴리스에 첨부합니다.

## 파일 전체 암호화

먼저 잃어버려도 괜찮은 테스트 파일로 연습하세요.

1. **플러그인 > NppShade > 환경 설정**에서 파일 전체 암호화를 켭니다. 확장자 입력란에 `nppshade;enc;npp`를 적습니다. `nppshade`만 입력해도 됩니다. **확인**을 누릅니다.
2. UTF-8 새 파일을 만들고 짧은 메모를 입력합니다.
3. 글자를 선택하지 않은 상태에서 **암호화**를 누릅니다. 저장 위치를 정하고 비밀번호를 두 번 입력합니다. 비밀번호를 잊으면 복구할 수 없습니다.
4. 편집기에는 평문이 표시되고 저장 파일에는 암호문이 기록됩니다. `note.txt`로 시작하면 보통 `note.txt.nppshade`가 만들어지고 원본 평문은 그대로 남습니다. 필요하면 `txt`, `ini` 같은 확장자를 더 등록할 수 있습니다.
5. 암호화 파일을 닫았다가 다시 열고 비밀번호를 입력합니다. 입력이 틀려도 대화상자는 닫히지 않아 다시 시도하거나 취소할 수 있습니다.

**저장 시 암호화 확인**은 저장할 때 암호 설정을 바꿀지 확인할지 정합니다. 끄면 기억된 설정으로 바로 저장합니다. 파일을 닫으면 해당 파일 저장에 쓰던 비밀번호는 지워지고, 다시 열 때 입력해야 합니다.

복호화를 취소하면 편집기에 암호문이 남습니다. 이를 평문처럼 편집하거나 저장하지 마세요. 파일을 닫았다가 다시 열거나 암호 블록 전체를 선택해 복호화를 다시 시도하세요.

### 확장자 규칙

확장자는 영문 세미콜론으로 구분합니다(예: `nppshade;enc;npp`). 앞뒤 공백과 맨 앞의 점은 제거되고, 대소문자는 구분하지 않으며 중복 항목은 제외됩니다. `*.enc`, 경로, `tar.gz` 같은 복합 확장자는 입력하지 마세요.

- 목록에 있는 확장자는 모두 파일 전체 처리 대상입니다.
- 새 암호화 파일 이름에 등록된 확장자가 없으면 첫 번째 확장자를 붙입니다.
- 기존 `.enc` 파일은 목록의 첫 번째가 `nppshade`여도 이름을 바꾸지 않습니다.
- 확장자를 바꾸는 것만으로 암호화되지는 않습니다. 헤더 없는 평문 `.enc` 파일은 열 때 비밀번호를 묻지 않습니다.

## 선택 영역 암호화

텍스트를 선택하고 **암호화**를 누르면 선택 부분만 암호 블록으로 바뀌며 나머지는 평문으로 남습니다. 복호화하려면 `<nppshade ...>` 헤더를 포함한 블록 전체를 선택하고 **복호화**를 누른 뒤 비밀번호를 입력합니다.

선택 영역이 없을 때 **암호화**는 확장자 처리가 켜진 경우 파일 전체를 처리합니다. **복호화**에는 선택 영역이 필요합니다. 유효한 헤더가 있는 암호화 파일은 열 때 자동 처리할 수 있습니다.

## 비밀번호와 고급 설정

처음 암호화할 때 확인을 위해 비밀번호를 두 번 입력합니다. 대소문자를 구분하며 공백, 문장 부호, 한글도 비밀번호에 포함됩니다. 도움말의 물음표는 설명을 열 뿐 비밀번호를 보여 주거나 복구하지 않습니다. 입력 중인 비밀번호는 **표시**로 잠시 확인할 수 있습니다.

유효한 헤더가 있는 파일을 열면 암호화 설정이 헤더에 기록되어 있어 비밀번호 입력만 표시됩니다. 수동 복호화에서는 예전에 Hex, Base32, Base64로 입력한 비밀번호를 위한 **비밀번호 인코딩** 항목도 사용할 수 있습니다. 인식 가능한 헤더가 없는 데이터는 전체 설정이 필요합니다.

일반적으로 기본값을 유지하세요. 주요 고급 설정은 다음과 같습니다.

| 항목 | 기능 | 일반적인 선택 |
| --- | --- | --- |
| 암호 알고리즘, 키 길이, 모드 | 데이터 암호화 방식을 결정 | AES/Rijndael, 256비트, GCM |
| 비밀번호 인코딩 | 입력을 UTF-8 또는 인코딩된 키 바이트로 해석 | 일반 비밀번호는 `utf8` |
| 표시 | 입력 중인 비밀번호를 잠시 표시 | 주변에서 화면을 볼 수 없을 때만 사용 |
| IV/솔트 인증 | 지원 모드에서 이 값들도 인증 | 켜 둠 |
| 출력 인코딩 | 암호문을 바이너리, Hex, Base32, Base64로 표현 | 텍스트 파일에는 Base64 |
| 솔트 | 암호화마다 파생 키를 다르게 만듦 | 헤더에 저장되는 무작위 값 사용 |
| scrypt, bcrypt, PBKDF2 | 키를 만들고 비밀번호 추측 비용을 높임 | scrypt 유지. 높은 값은 시간과 메모리를 더 사용 |
| IV | 암호화 초기 데이터 제공 | 무작위 생성. 0 또는 사용자 지정 값 재사용 금지 |
| HMAC | 별도 키로 헤더와 암호문 인증 | 선택 사항. 기본 GCM에도 인증 기능이 있음 |

## 프리셋 키

프리셋 키는 HMAC 및 키가 있는 해시에 쓰며 암호화 비밀번호와는 다릅니다. 내장 프리셋 이름은 `nppshade`입니다. 새 키를 만들려면 이름을 입력하고 **무작위**, **추가**를 차례로 누릅니다. 키는 16바이트의 Base64 표현(보통 24자)으로 저장됩니다. 삭제할 수 없는 내장 항목을 포함해 최대 20개까지 저장할 수 있습니다.

사용자 키는 설정 파일에 저장됩니다. Base64는 인코딩이지 암호화가 아닙니다. 내장 키는 공개되어 있으므로 실수로 바뀌었는지 확인하는 용도로만 쓰세요. 비밀 인증에는 직접 키를 만들고 설정을 백업하세요. 파일에는 프리셋 번호가 기록되므로 다른 PC에서도 같은 번호에 같은 키가 필요합니다. 앞 항목을 삭제하면 뒤의 번호가 바뀔 수 있습니다.

## 해시

텍스트를 선택하고 **해시**를 엽니다. **삽입**은 선택 영역을 요약값으로 바꾸고 **복사**는 문서를 유지한 채 결과를 복사합니다. 원문을 남기려면 **복사**를 사용하세요. 일반적인 확인에는 SHA-256이 적합합니다. MD5는 의도적인 위조를 막는 용도로 적합하지 않습니다. 해시로 원문을 되돌리거나 암호화할 수 없습니다.

요약 길이는 출력 바이트 수이고 인코딩은 표시 형식을 정합니다. 키 기반 알고리즘에서 같은 결과를 내려면 입력, 알고리즘, 키가 모두 같아야 합니다.

## 난수

바이트 수, 문자 제한, 출력 인코딩을 선택합니다. **삽입**은 선택 영역을 바꾸거나 선택이 없으면 커서 위치에 넣습니다. **복사**는 문서를 수정하지 않습니다. 제한 없는 바이너리에는 보이지 않는 문자가 포함될 수 있어 직접 입력할 비밀번호로는 적합하지 않습니다. Hex, Base32, Base64 출력은 원래 바이트 수보다 문자가 많습니다.

## 인코딩 변환

텍스트를 선택하고 **인코딩 변환**을 엽니다. **원본**에 현재 형식, **대상**에 원하는 형식을 지정합니다. 예를 들어 `hello`의 Base64 표현은 `aGVsbG8=`입니다. **변환**은 선택 영역을 바꾸고 **복사**는 원문을 유지합니다. 줄바꿈, 줄 길이, 대문자 옵션은 서식만 변경합니다. 인코딩은 되돌릴 수 있으므로 비밀을 보호하지 않습니다. 암호 헤더와 변환 창은 기본 Base32 알파벳이 다르므로 혼용하지 마세요.

## 화면 및 자주 묻는 질문

대화상자는 화면 DPI와 사용 가능한 작업 영역에 맞춰 배치됩니다. 오래된 Notepad++에서는 배율이 다른 모니터 사이를 이동할 때 제약이 있을 수 있습니다.

- **비밀번호가 거부됩니다.** 비밀번호와 파일이 완전한지 확인하세요. GCM, CCM, EAX는 비밀번호나 데이터 불일치를 감지합니다. 인증 없는 구형 모드는 잘못된 비밀번호를 확실히 감지하지 못할 수 있습니다.
- **편집기에는 평문, 파일에는 암호문이 보입니다.** 편집 중인 내용은 메모리에 있고 저장할 때 암호화됩니다. 다시 보려면 파일을 열고 비밀번호를 입력하세요.
- **비밀번호를 잊으면 복구할 수 있나요?** 복구할 수 없습니다. 도움말, 프리셋 키, 확장자 변경으로 암호화를 우회할 수 없습니다.
- **백업도 암호화되나요?** Notepad++ 세션 스냅숏, 자동 백업, 다른 앱이 만든 복사본은 플러그인이 관리하지 않습니다. 원본 평문 파일이 디스크에 남을 수도 있습니다.
- **설정 파일 위치는 어디인가요?** 일반 설치는 `%APPDATA%\Notepad++\plugins\config\nppshade.xml`, 포터블 설치는 `plugins/config/`입니다. 편집 전 Notepad++를 종료하고 백업하세요.
- **인증 키를 묻는 이유는 무엇인가요?** 파일에 사용자 HMAC 키가 설정되어 있습니다. 본문 암호화 비밀번호와 다를 수 있습니다.

## 소스 빌드

Visual Studio 2022 C++ 데스크톱 개발 도구와 Windows SDK를 설치하고 Developer PowerShell에서 실행합니다.

```powershell
msbuild projects\msvc2017\nppshade.sln /m /t:nppshade /p:Configuration=Release /p:Platform=x64
```

x64 DLL은 `bin/nppshade/x64/Release/NppShade.dll`에 생성됩니다. 소스에는 명령줄 도구 프로젝트도 포함되어 있습니다. 사용법은 `--help` 출력을 참조하세요. 데스크톱 프리셋 키는 명령줄 도구에서 직접 사용할 수 없습니다.

문제를 보고할 때는 [프로젝트 페이지](https://github.com/Rinkomochi/NppShade)에 Notepad++와 플러그인 버전, 재현 절차를 적어 주세요. 실제 비밀번호나 개인 파일은 첨부하지 마세요.
